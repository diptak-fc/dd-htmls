Setup & troubleshooting

1. Turn on GitHub Pages (required)

On github.com, clicking an .html file shows its source code, not the rendered page. GitHub Pages publishes the same files as a real website so they open properly.

  1. Go to your repo → Settings → Pages.
  2. Under Build and deployment, set Source to Deploy from a branch.
  3. Choose your branch (main) and folder / (root), then Save.
  4. Wait about a minute. Your site appears at https://<username>.github.io/<repo>/.

Visit that URL — not the github.com URL — and this index will populate itself.

2. Where this file goes

Put it in the root of the repo, named index.html. GitHub Pages serves it automatically as the landing page, so the bare site URL becomes your master index. Links are built relative to the repo root, so pages in subfolders resolve correctly.

3. If the list stays empty

  • Private repo: the GitHub API won't list files without a token. Make the repo public, or ask for the static-list version instead.
  • Opened from your desktop (a file:// path) or from github.com: the page can't detect the repo. Use the Pages URL.
  • Rate limited: GitHub allows 60 unauthenticated API calls per hour per IP. Wait an hour, or set the override below.

4. Manual override

If auto-detection guesses wrong — most likely on a user site (username.github.io) rather than a project site — edit the top of the script in this file:

const CONFIG = {
  owner:  "your-github-username",
  repo:   "your-repo-name",
  branch: ""     // blank = repo default branch
};

5. Adding pages later

Commit a new .html file anywhere in the repo. It appears here on the next load — no edit to this file needed. Titles come from each page's <title> tag, so give your pages good titles.
